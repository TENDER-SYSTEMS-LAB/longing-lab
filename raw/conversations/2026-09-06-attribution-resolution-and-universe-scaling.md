# Working session — attribution resolution and universe scaling

2026-09-06. Working session held while the third review round was being collected. The session did not review any model output; it worked on what the terminal actually prints each week, and what that implies for how many factors exist and how many securities are listed.

This is a compiled record of the substantive exchange, not a byte-exact export. Repository mechanics from the same session — commits, hash sweeps, lint — are omitted. Where a decision or a position was stated by the user, the user's words are reproduced verbatim in Korean and marked as such.

---

## 1. Request

The user asked for a concrete explanation of the attribution ledger before deciding anything about it:

> 3으로 넘어가기 전에 attribution ledger가 뭔지 구체적으로 설명해주고, 그다음 작업에 들어가줘.

## 2. What an attribution ledger is (LLM explanation)

Each week, for each security, the price move is decomposed into named lines whose sum is exactly the return. The institution does not print `27.43` and stay silent; it prints the breakdown beside it.

Worked example given:

```
LETTER  Handwritten Letter          27.43 → 27.86      +1.57%
week ending 2026-09-04

  Latency Collapse                  −0.31%
  Functional Substitution           −0.44%
  Predictive Pre-selection           0.00%
  Dematerialization                 −0.18%
  Attentional Slack                 −0.22%
  Friction Premium                  +1.86%
  Status Coding                     +0.74%
  ──────────────────────────────────────────
  Factor contribution               +1.45%
  Security fundamentals             +0.09%
  Positioning                       +0.03%
  Interaction / residual             0.00%
  ──────────────────────────────────────────
  Total return                      +1.57%
```

Each line is one multiplication: the security's assigned exposure to a factor times that factor's move for the week.

Three points were made about why this object is central:

1. The ledger lines are what the audience actually reads. The factor list is not internal machinery; it is the vocabulary of causes the work speaks in.
2. Choosing the factor count is therefore choosing how many lines appear on screen. The same week rendered with a five-factor set collapses four distinct human changes into one line; rendered with a twelve-factor set it separates them, but thereby claims an ability to distinguish them.
3. Making the lines sum exactly is always achievable. The risk is manufacturing certainty that does not exist in order to reach an exact sum.

## 3. Resolution decision (user)

Asked how many lines the weekly ledger should carry, the user answered:

> 9개 안팍으로 가되, 종목수가 늘어날걸 고려해서, 종목이 늘어나면 줄 수가 늘어나도록 해야겠다. 노출되는 Factor가 늘어나니까.

Read as: start near nine displayed factors, and let the number of ledger lines grow as the security universe grows.

This is a rule rather than a set selection. It makes the factor count a function of the universe size instead of a constant, and generalizes the "declared but unpriced" device — which one second-round review applied to two individual factors — into standing policy.

## 4. What "unexplained movement" means

The user asked:

> 여기서 설명할 수 없는 움직임이라는게 뭔가?

LLM answer given: in a real market, residual is what a model fails to explain about an observed price. In LONGING the price is generated by the model, so the residual is structurally zero and nothing is unexplained in that sense.

The real gap is different. Events are authored, and each must be translated into factor moves. Some events have no word in the factor vocabulary. Worked example: the last large film-processing chain closes. Cultural prestige is unchanged, material preference is unchanged, digital capability is unchanged. What changed is whether the practice can be performed at all — infrastructure viability, which none of the six candidate sets carries as a macro factor.

Four possible terminal behaviors were laid out: force the move into a factor that means something else; book it to the security-fundamentals line; print a named `Unexplained` line; or let the price not move at all, so the world changes and the market fails to notice.

## 5. User position on unattributable events

> 이런 일은 없어야 한다.
> 따라서 factor는 추상적인 항목이지만 많아야 하고 그 많은 factor만큼 커버하는 종목수도 많아져야 할 것 같아.
> 내가 틀린부분이 있으면 지적해 달라.

Position: unattributable events should not occur at all. Factors should be abstract but numerous, and the security count should grow to match.

## 6. Critique offered in response (LLM)

Three points, one of them a correction of the LLM's own framing.

**The example was mis-framed.** Infrastructure viability cannot be a macro factor: it loads on Film Photography, Physical Media and Live Performance and is near zero on Solitude or Waiting for a Reply. A factor supported on three of eleven constituents is a security-level effect, which is why one second-round review left its own thinly supported factor unpriced. The ledger already has three layers — factor contribution, security fundamentals, positioning — and the film-lab closure belongs in the second layer from the start. The option earlier presented as a lesser choice was in fact the architecturally correct one for that event.

**Adding factors past what the universe supports adds no coverage.** Two factors whose exposure vectors are identical across all securities always move in fixed proportion. The ledger prints two lines that can never say different things: one factor with two names.

**"This should never happen" has two solutions, and one of them is silent.** Widen the vocabulary, or narrow the world to fit the vocabulary. Because events here are authored, the second happens by default and without anyone deciding it: an event that is real, thematically apt, and unwriteable in the current vocabulary simply never gets written, and the work quietly becomes thinner.

A three-layer allocation rule was proposed on that basis, with `Unexplained` retained as a rarely firing mechanism whose firing rate serves as an instrument reading rather than as a display element. This was an LLM proposal; the user did not respond to it directly before moving to the next question.

## 7. User intent on Unexplained, and the N/K question

> 나는 작품 설계단계에서 Unexplained를 최대한 많이 찾고 승격하고 싶어.
> 너가 말한대로, N에 묶인 상한이 factor인데 반대로 생각하면 factor가 늘면 N을 늘려버리면 해결되는 문제로 보이는데 뭐가문제일까?

Two things: an intent to deliberately provoke `Unexplained` during design in order to discover factors worth promoting, and a challenge to the identification constraint — if the factor ceiling is set by the number of securities, and securities are authored, raise the number of securities.

## 8. Response to the N/K challenge (LLM)

The direction was agreed. Four qualifications were offered.

**Raising N need not raise rank.** The working ratio of roughly one factor per three securities assumes the added securities supply genuinely different exposure patterns. The current eleven are nearly all slow analog practices being displaced by technology; adding thirty more of the same kind leaves effective rank roughly where it was. Separating two factors requires securities that respond to one and not the other — including securities with zero or opposite loading. To separate coordination from spatial proximity, the universe needs a practice where scheduling matters and distance does not, and one where the reverse holds.

**The ratio is the wrong rule for this model.** In a conventional factor model many securities are needed because betas are estimated from data. Here betas are assigned, so the arithmetic works at any count. What fails is observability of the distinction in the output. A better test was proposed: a factor earns a ledger line when at least one security in the universe responds to it differently from every other factor. This is checkable per factor and answers whether a specific factor can be promoted now, rather than how many factors are permitted in total.

**Three constraints pull against each other when adding securities.** Statistically the exposure patterns must be diverse rather than merely numerous. Thematically each practice must carry the sense of loss the work is about, though this tension may be weaker than assumed — the coordination-sensitive examples suggested in the second round are thematically strong. For falsification, some added practices must be in genuine secular expansion; selecting only disappearing practices embeds aggregate decline in the universe rather than in any equation, which two reviews named as the largest risk to the work.

**The scale is the real cost.** Forty-five securities against fifteen factors is a 675-cell exposure matrix, every cell a defensible judgment, and the matrix grows as the product of the two counts. Separately, eleven tickers and forty-five tickers are different works: eleven is a list a viewer holds in mind, forty-five is an index they scan. That may suit the research-house form better, but it is a change that should be decided rather than arrived at.

The concluding observation: nothing is wrong with raising the universe. The problem is that it has been treated as a variable dependent on the factor decision when it is closer to the reverse — the choice of which practices are listed largely determines which factors can exist.

## 9. Unexplained as a design instrument (LLM proposal, responding to user intent)

The user's stated intent was endorsed and given a mechanism. The ground-truth event recovery test proposed by the third-round reviewer can be run as a design tool rather than a judging tool:

1. Deliberately author events, especially ones suspected to fall outside the current vocabulary.
2. Attempt to allocate each to one of the three ledger layers.
3. Where none fits, `Unexplained` fires.
4. For each firing, ask whether the cause spans several securities, making it a factor candidate, or is confined to one, making it a security-fundamentals entry.
5. Accumulated factor candidates then imply which securities are needed to separate them.

This makes the factor list and the security list emerge from one process instead of being fixed separately, and dissolves the ordering problem of whether factors or securities come first: both are derived from the event list.

A next work item was proposed on that basis — write thirty to fifty events first, then allocate — but no order was chosen by the user in this session.

## Status of the material in this record

Stated by the user as decisions or positions: the near-nine initial resolution with growth tied to universe size; that unattributable events should not occur; that factors should be abstract but numerous with the security count growing to match; and the intent to provoke `Unexplained` during design in order to find factors worth promoting.

Proposed by the LLM and not confirmed by the user: the three-layer allocation rule; the per-factor separability test replacing the one-in-three ratio; retaining `Unexplained` as a rarely firing mechanism and treating its rate as an instrument reading; and the proposal to write an event list before fixing either factors or securities.
